# Android application

Native Android app using Kotlin and Jetpack Compose. The current slice supports multiple local homes, manual ingredient and measured recipe entry, approximate stock levels, recipe search by name/ingredient/style, family-grouped versions, ready-to-make and missing-one/two-required-ingredient filters, recipe yield scaling, and per-member tasting notes. At the shop separates restocks from spirit recommendations based on newly makeable recipe families. It consumes `shared/core` for SQLite and domain logic.

Recipe variants can be archived with a deletion revision and tombstone while preserving their history. Household JSON backups are available from More: export to a file, select a backup to preview, resolve any conflicts, then apply the import. Canceling the preview leaves local data unchanged. The Recipes screen offers an explicit local install of the eight-record offline starter catalog; source entries remain read-only, and editing creates a household copy. Camera scanning requests permission only after the user taps Scan; barcode entry remains available manually if permission is denied. The Android forms support measured recipe lines, inventory levels, locations, and member selection. AI and external product lookup are not included. Build instructions are in the root README. See [ADR-0008](../../docs/architecture/ADR-0008-kotlin-multiplatform-repository.md), the [Phase 1 plan](../../docs/planning/PHASE_1_PLAN.md), and the [implementation status](../../docs/planning/PHASE_1_STATUS.md).

## Sideload preview builds

Pushes to `main` and manually dispatched workflow runs upload a debug-signed APK as a GitHub Actions artifact for 30 days. GitHub downloads that artifact as a ZIP archive: extract it first, then open `androidApp-debug.apk` from Files to start Android's package installer. Pull requests run verification and builds but do not publish an artifact. The APK is a development preview, not a production release. It uses package `com.davidhayesbc.cocktails`, minimum Android API 26 (Android 8.0), and a CI version name containing the run and commit identity.

Ordinary Actions artifacts are debug-signed by the hosted runner and may not update an APK signed by another runner. Trusted preview-release builds use a dedicated preview signing key; they are not production or store builds. Always export a household backup before testing a different preview channel.
