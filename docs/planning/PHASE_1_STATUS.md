# Phase 1 implementation status

This is a snapshot of implementation and verification, not a release-readiness claim. The acceptance criteria refer to [MVP_SPEC.md](../product/MVP_SPEC.md#6-mvp-acceptance-criteria).

## Delivered foundation

- Android debug app and Kotlin Multiplatform shared core are in place; Android CI runs build/unit/lint/APK verification independently from the headless emulator smoke job. Exact-SHA Actions run [40164681782](https://github.com/davidhayesbc/CocktAIls/actions/runs/40164681782) passed both jobs on `0835114af258eeb3173680a7b2bf9cf3c06ef20c`: the APK was built and the API 35 emulator passed offline recipe creation plus activity-recreation persistence. That older SHA does not validate the scanner changes at `41ecab3` or the catalog at `7c804e2`; this environment received HTTP 403 when checking the newer Actions runs, so their results are not asserted here.
- A manual, trusted-main-only preview release workflow uses the approved repository secrets `COCKTAILS_PREVIEW_KEYSTORE_BASE64` (PKCS#12) and `COCKTAILS_PREVIEW_KEYSTORE_PASSWORD`, signs with alias `cocktails-preview`, verifies the APK certificate, then publishes a public GitHub prerelease using job-scoped `contents: write`. The first release workflow was dispatched once for `0346502192fb6720fafa25f8a2f6ad676723214e` as run [40216003368](https://github.com/davidhayesbc/CocktAIls/actions/runs/40216003368); its final publication result is not available from this environment. No production signing or store release is configured.
- SQLDelight schema v5 adds optional local product-photo storage. Populated v1, v2, v3, and v4 database fixtures migrate to the current schema while preserving existing IDs/data; the v4-to-v5 photo-column migration is tested directly. Canonical UUIDv7 generation, family-level shop unlock counting, recipe-family association, tasting-note author attribution, and revision payload/parent links are covered.
- Household recipe variants can now be archived with an immutable deletion revision and tombstone. Archived variants stay in storage/history and disappear from browse results; repeated archive attempts do not create another deletion.
- Versioned household JSON backups can be written/read with Android's document picker. Import is size/schema/reference checked, staged for preview, cancelable without writes, and committed in one database transaction. Device-local preferences and provider/coordinate settings are excluded.
- Import conflict review compares revision ancestry, never relies on device timestamps, supports keep-local/use-backup/field merge, and writes a merge revision with both branch heads as parents. Reimporting an older branch after merge does not roll back the selected result.
- Apply rechecks the preview fingerprint inside the database transaction, preserves the exact revision/time for an existing tombstone on stale live-backup reimport, and rejects a combined household state that would exceed the 10 MiB backup limit.
- Product photos are optional and stay local unless the household backup is explicitly exported. Android's system photo picker accepts a user-selected image, applies orientation, re-encodes to JPEG to remove EXIF/XMP metadata, and enforces a 1 MiB per-image limit. Household bundles validate JPEG markers, metadata-free segments, checksum, references, and a 6 MiB aggregate photo limit before atomic apply. A two-database round trip and checksum-tamper no-write case are tested. No image lookup or cloud storage is used.
- Local household and member profiles, multiple homes, per-home approximate inventory, persisted manual home/member choices, recipe entry, grouped variants, style filters, tasting notes, and the initial At the shop spirit ranking are implemented.
- Recipe discovery now filters by what is on hand, exactly one missing required ingredient, or up to two missing required ingredients. Optional lines do not block availability and repeated use of one ingredient counts once.
- Recipe entry now accepts measured ingredient lines and an original yield; the detail view scales known quantities for a selected serving count. Quantity/yield persistence is covered by a two-database bundle round-trip test.
- Recipe variants can be edited without replacing immutable revision history or stable ingredient-line IDs, duplicated within their existing family, and merged after divergent two-device edits. Duplicate variants retain source attribution and measured yields.
- Family favorites are member-attributed household records. Removal writes a tombstone, divergent changes enter conflict review, and stale backups cannot restore a removed favorite. Recently made events are persisted, attributed to member/location, and transferred in household bundles.
- Optional foreground location selection uses one approximate coarse fix while the app is open. Users save a private radius for each home on this phone; overlapping/no-match areas never guess, and a manual home change pauses automatic switching until resumed. The selected home and override survive process recreation. At the shop snapshots its destination and pantry for the whole session.
- UPC/EAN barcode capture uses an on-device CameraX/ZXing preview; camera permission is requested only after tapping Scan. Manual entry stays available offline. Check digits and normalized GTIN duplicates are validated, the original code and user-confirmed product label/brand are retained, and product association plus pantry entry commit together. Household backup carries the product and revisions; no external product lookup or dataset is bundled. Scanner luminance handling now honors image crop/row/pixel strides and rotates the copied luma frame before ZXing decoding. Local UPC-A decode tests pass at 0°, 90°, 180°, and 270°; instrumentation covers permission prompt grant/denial, manual fallback, live preview plus analyzed frames, repeated open, Back dismissal, and activity recreation. Instrumentation runtime and physical Pixel camera verification remain pending. See [ADR-0009](../architecture/ADR-0009-offline-barcode-capture.md).
- The reviewed eight-record Wikipedia/IBA starter pack is bundled separately at `catalog-packs/iba-wikipedia-starter/`. The user explicitly adds it from the recipe screen; installation is local, transactional, and idempotent, and existing household recipes/notes are not overwritten. Each source record retains its permanent revision/history links, original ingredient text, attribution, CC BY-SA 3.0 license and modification record in household backups. Catalog records are read-only; editing creates a household-owned copy. The scoped source review and its limits are in [CATALOG_DATA_REVIEW.md](CATALOG_DATA_REVIEW.md). Final-SHA CI for this catalog work is pending.
- User-provided CSV and JSON recipe files now have a separate on-device import path from household backups. It parses and maps fields in a preview, requires source/license/attribution metadata, validates measurements/yield/style and duplicate external IDs, and commits the whole batch atomically. Import source records keep their provenance in household backups. A source record reimports idempotently; changed content under an existing source ID rejects the whole batch. Family and compatible-variant associations require explicit selection; confirmed source links can later be unlinked or moved to another formulation-compatible variant, with revisions preserving the association history.
- No credentials, model providers, or network service are required for the app's current workflows.
