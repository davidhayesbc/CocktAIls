# BC reference product seed

The app bundles the July 2026 BC public product CSV, its retained catalogue metadata, and a generated reference catalogue. `tools/product-catalog/build_bc_products.py` regenerates the JSON and audit report offline; `--check` verifies deterministic output. CSV SHA256: `8b426567e9342e1205dcf5fb875c3c397f6e3f5f9d7e820a1ca4e205fb068406`. Original retained metadata SHA256: `031d9b0defeb16cded2fda5e98fb7983ad650a210dbce437d1d5fafce402c654`. Distributed minimal metadata projection SHA256: `e6fc4f6979c170a13357951ace9caab1dd985048a5786348601f63628c158d27`; incidental contact details are omitted.

Migration 10 adds separate reference tables. Installation validates the complete pack before replacing that source's snapshot in a single transaction. A content-identical install is a no-op; older dates/revisions and changed content with an unchanged revision are rejected. Newer bundled snapshots may replace only reference data. Household products, recipes, pantry items, draft edits and explicit clears are not updated. Reference records are not exported as owned household products. Clearing household data or restoring an export does not convert the public catalogue into inventory.

Household barcode matches take precedence. Only a unique, eligible reference key is returned when no household record matches. Reference matches have no household product/ingredient IDs. Scanning may prefill a new review draft; confirmation is still required before creating owned inventory. Matching accepted name, size and ABV facts receive BC provenance on confirmation. Edited/cleared values are not falsely attributed to BC. The add-bottle screen identifies reference matches distinctly and shows attribution.

Scanner and web GTIN validation are unchanged. Source-only recovery accepts strictly numeric strings, pads on the left to GTIN-14 and verifies the check digit. Eight-digit and shorter source values are quarantined because this lossy CSV cannot distinguish EAN-8/UPC-E from zero-stripped UPC-A. Native eight-digit scans are not expanded into reference matches. 12/13/14-digit representations of the same GTIN can match. Barcode collisions are excluded even when names agree: packaging is part of product identity.

Verified source: 8,224 rows, including 1,581 spirits; 654 missing UPCs, three invalid check digits, 7,567 valid rows and 7,566 unique normalized keys. Eligible single-container reference matches: 6,988, including 1,561 spirits. Exclusion reasons overlap. The two Michelob Ultra Zero rows share key `00062067427152` but contain 1 and 6 units; both remain excluded. All source rows remain available in the bundled data/audit, including excluded rows.

Classifications are conservative: the BC class is retained as the proposed ingredient name, Spirits maps to the existing generic Spirit category, and other source categories remain unchanged. This does not equate gold tequila with reposado/añejo, infer a brand, or replace the user's drink category taxonomy. Country, subcategory, raw UPC, unit count, source dates and licence metadata remain in the reference record.

See `catalog-packs/bc-products/NOTICE.md` for attribution, the unresolved `isopen=false` metadata inconsistency and snapshot-age limitations. No private 18-bottle export was found locally by filename; no coverage claim is made for that inventory. Device startup timing and real scans require emulator/device validation before release.
