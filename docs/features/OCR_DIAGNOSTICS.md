# Label OCR diagnostics

Standard diagnostics copied or exported from the diagnostics dialog include `labelOcr`, alongside the existing web lookup report. No detailed-capture opt-in is required. This journal contains **no OCR transcript, photo, barcode, field value, evidence quote, prompt, model output, path, credential, or exception message**. It does not enable detailed OCR capture.

The bounded on-device journal retains the last 12 scheduled attempts. Correlations are opaque SHA-256 references for the draft, session, photo and enrichment attempt, with a separate request reference for repeated work. A context reference also detects a corrected barcode without exporting it. The export compares each record to the current stored draft and attempt; earlier requests and changed/removed photos are historical (`isCurrent=false`). If the repository snapshot is unavailable, currentness is unknown rather than claimed. An absent current record does not mean recognition succeeded; older app builds did not record this phase.

Lifecycle states include queued, running, completed, skipped, failed, cancelled, stale and interrupted. Recognition and downstream local label-AI states are separate. Reasons distinguish missing photos, inactive queues, changed attempts/photos, enqueue or storage failures, invalid images, recognition timeout/failure, no text, disabled local AI, missing model, foreground restrictions, invalid model responses and model runtime errors. Explicit OCR scalar facts can remain useful when local AI is skipped or fails; a completed worker with a failed label-AI stage means that fallback evidence was saved, not that model generation succeeded.

`recognitionMs` and `labelAiMs` are nested within `workerElapsedMs`. They are not additive to each other plus worker time, and are never added to the independent web report's network/AI/end-to-end totals. Worker elapsed time includes waiting for the serialized local extraction slot; queued/started timestamps distinguish scheduling delay. Durations use monotonic clocks during execution; all exported duration values are bounded.

Results report only supported, unresolved and conflicting field names and counts. Rejections distinguish conflicts from lack of supported evidence. They do not imply every unresolved field was explicitly proposed by the model. The normal evidence store and manual-edit precedence remain unchanged.

Writes and lifecycle updates are serialized. Late events from superseded requests cannot overwrite current work. Queueing failures are observed through WorkManager's operation future. User cancellation is terminal and recorded for individual drafts and sessions. A system-stopped worker records `INTERRUPTED/WORK_STOPPED`; only a new start of that same current request can resume it. Superseded requests and user-cancelled work cannot restart their diagnostic record. Stale, cancelled and interrupted states also finish active child stages with the corresponding reason, preserving already completed stages. A running record owned by a prior process exports as interrupted; a restarted worker resets its stage timings and increments the WorkManager retry counter. Queued work remains queued across process restart. Clearing local diagnostics also clears this journal.

Validation includes journal persistence, scoped exports, new-photo/new-attempt replacement, cancellation and late completion, process restart and retry, bounded retention, malformed persisted fields, private data canaries, label-AI skip/failure/parse/cancellation outcomes, and preservation of existing web timings in the combined export. Emulator and physical-device tests remain necessary to validate real ML Kit timing and OS interruption behavior.

## Preview 26 follow-up observability

Each new request records a fixed scheduling trigger (photo saved, intake restored, lookup queued, web lookup finished, manual draft created, or unknown). A superseded request records the replacing trigger. This identifies future replacement causes; it cannot recover the trigger of older records. Web completion currently deliberately requests label extraction again with the latest independently verified web context, while label evidence must still quote only the photo text.

Reports also include bounded input-character and explicit/model candidate counts. `NO_CANDIDATES` distinguishes no proposed fields from `NO_ACCEPTED_FIELDS` after validation; neither weakens the validator. An active snapshot reports time since its latest diagnostic update and whether it is waiting for WorkManager or the local extraction slot. `requestAgeAtStartMs` measures age since scheduling at each worker start (including earlier attempts after a retry); it is not claimed to be pure queue time. Label-AI slot waiting is measured separately within worker time. These counts and timings contain no raw OCR or model output. No raw-text capture is enabled by this change.
